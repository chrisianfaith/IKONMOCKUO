How one ID becomes one account, never two: the diagram below is the exact lifecycle of a single Practitioner ID, from the moment the Super Admin loads it to the moment it's spent.

1 · Imported

Super Admin bulk-loads the ID. Status in the database: unused.

→
2 · Entered at sign-up

Practitioner types the ID. Server checks it exists and is still unused — green check shown.

→
3 · Account created

Registration completes. In the same database step, the ID flips to used and locks to that account.

→
4 · Reused attempt

Anyone else entering that same ID is blocked — "This Practitioner ID has already been registered."

Every admin sign-in is logged — device, location, and time — and visible in the activity log for review.

Why it's separate from the Practitioner login: a different URL, a plain unbranded screen, and a mandatory second verification code (on top of the password) make this account meaningfully harder to reach or guess than a regular Practitioner sign-in. Only accounts explicitly flagged role = super_admin in the database can use this screen at all — creating one is a manual, deliberate action, never a self sign-up.
